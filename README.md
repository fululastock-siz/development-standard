# AI開発の共通標準

ChatGPT、Codex、Claude、Gemini、別アカウント、別PCへ交代しても、GitHub上の記録から作業を再開するための文書テンプレートです。`fululastock-siz` は現時点でGitHubの個人アカウントですが、同じ共通テンプレートの仕組みを使えます。

## 記録の役割

| 記録 | 役割 |
| --- | --- |
| Issue | 作業前の目的・現状・計画・完成条件。進捗も更新する |
| commit | 実際に変更した内容の履歴 |
| `HANDOVER.md` | 今の状態、残作業、次の一手 |
| PR | 作業結果、確認結果、レビューの記録 |
| `PROJECT.md` | プロジェクト全体の設計と不変条件 |
| `DECISIONS.md` | 設計判断と理由 |
| `AGENTS.md` | AIが守る開発ルールと固有の制約 |
| `TASKS.md` | 複数作業の進捗一覧 |

## 毎回の作業手順

1. 対象リポジトリの現状、既存ルール、既存Issueを読む。
2. **コード変更前にIssueを作成または更新**し、目的・現状・作業計画・変更予定ファイル・変更しないファイル・完成条件・テスト項目・作業ブランチを記録する。記録前に実装しない。
3. 既定ブランチから作業ブランチを作る。`main` などの既定ブランチへ直接pushしない。
4. 小さく意味のある単位でcommitし、Issueのチェックリストと検証結果を更新する。
5. 終了・中断前に `HANDOVER.md` と `TASKS.md` を更新してcommitする。設計判断は `DECISIONS.md` に記す。
6. PRにIssue、変更内容、検証結果、残るリスクをまとめ、レビュー後に統合する。

## 既存リポジトリへの導入

一律の自動上書きはしません。既存の `AGENTS.md` に本番運用やデプロイの固有指示があり、その保持が必要だからです。

1. GitHubで対象リポジトリを開き、既存の `AGENTS.md`、README、`.github/ISSUE_TEMPLATE`、PRテンプレート、`CONTRIBUTING.md`、ブランチ保護設定を確認する。
2. 共通の [Issueテンプレート](https://github.com/fululastock-siz/.github/tree/main/.github/ISSUE_TEMPLATE) が表示されるか確認する。対象側に独自のIssueテンプレートや設定があれば共通一式は使われないため、既存ファイルへ必要な項目を統合する。既存のPRテンプレートや `CONTRIBUTING.md` も優先されるため、内容を見て統合する。
3. 対象のIssueに、導入の目的・現状・計画・対象ファイル・対象外ファイル・完成条件・確認項目・作業ブランチを記録する。
4. 作業ブランチを作り、既存の `AGENTS.md` へ共通の作業開始・引き継ぎルールを**追記または統合**する。元の固有指示は削除しない。`PROJECT.md`、`TASKS.md`、`HANDOVER.md`、`DECISIONS.md` がない場合は、テンプレートを元に新規作成する。既にある場合は差分を確認して必要箇所だけ追加する。
5. 個人情報・認証情報・本番設定値が入っていないか確認する。実行可能な確認を行い、結果と未確認事項をIssueに記す。
6. 変更をcommitしてPRを作成する。PRのレビュー後に統合し、テンプレートと引き継ぎ文書がGitHubで読めるか確認する。

### 導入チェックリスト

- [ ] 既存文書、テンプレート、ブランチ保護設定を確認した
- [ ] 実装前にIssueへ必須8項目を記録した
- [ ] 作業ブランチで変更し、既存の固有ルールを保持した
- [ ] 必要な文書だけを追加または統合した
- [ ] 機密情報が差分にないことを確認した
- [ ] 動作確認結果と未確認事項を記録した
- [ ] 中断時の現在地がIssueまたは `HANDOVER.md` から分かる
- [ ] PRを作成し、レビュー後に統合した

## 別AI・別PCで再開する

1. GitHubで対象のIssueを開き、目的、完成条件、チェックリスト、作業ブランチを読む。
2. 対象ブランチのcommit履歴、未統合のPR、差分を確認する。作業中のPCに未pushの変更がある場合、GitHubだけでは復元できないため、そのPCの変更を確認する。
3. `AGENTS.md`、`PROJECT.md`、`TASKS.md`、`HANDOVER.md`、`DECISIONS.md` を読み、Issueと実際の差分を照合する。
4. 未完了箇所から作業し、確認結果をIssueへ追記する。終了・中断前に再び現在地を更新する。

再開依頼の例: 「`<リポジトリURL>` の Issue #`<番号>` と作業ブランチを確認し、commit履歴・差分・AGENTS/PROJECT/TASKS/HANDOVER/DECISIONSを読んで、未完了部分から続けてください。」

## 適用範囲と限界

共通の [`.github` リポジトリ](https://github.com/fululastock-siz/.github) はIssue・PRテンプレートなどを配布します。`AGENTS.md` などの独自文書は各リポジトリへ自動継承されません。また、文書だけでは直接pushを技術的に禁止できません。各リポジトリの設定で、既定ブランチへのPR必須ルールと必要なレビューを設定してください。変更前に既存の保護設定と利用可能なプラン・権限を確認します。

公開リポジトリなので、個人情報、認証情報、非公開の構成値は書かないでください。
